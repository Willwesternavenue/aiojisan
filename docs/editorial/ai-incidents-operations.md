# 国内AIインシデント一覧：運用ルール

対象ページ：`/incidents`（実装は `src/pages/incidents/index.astro`、データは `src/services/editorial/incidents.ts`）

データはリポジトリ内のTypeScriptファイルで持っています。追加・修正はコミットとして残るので、
いつ・何を直したかが後から追えます。件数が増えて管理が重くなったら Supabase に移します
（`AiIncident` 型をそのままテーブル定義に使える形にしてあります）。

## 掲載基準

次の4つをすべて満たすものだけを載せます。

1. 国内の組織・サービスが関係している。
2. AIの利用または提供が原因の一部になっている。
3. 一次情報で確認できる（当該組織の発表、行政・委員会の公表、当事者の報告書）。
   報道だけで当事者の確認が取れていないものは載せない。
4. 事実として書ける範囲が確定している。推測や評価は書かない。

「AIが関係していそう」という報道だけのものは、確認が取れるまで保留にします。
一覧の価値は網羅性ではなく、載っているものが確認済みであることです。

### 運用上の判断（2026-11-03）

- **レベル2の自動運転中の事故も対象に含める。** 運転支援であっても、システムの判断が
  物理的な接触につながった事例は `physical-safety` として扱います。
- **当該組織の公式SNSアカウントでの発表も一次情報として認める。** プレスリリースを出さず、
  公式Xでのみ謝罪・説明を行う例があるためです。この場合、`url` は投稿単体の permalink
  （`https://x.com/<account>/status/<id>`）にします。アカウントのトップページしか分からない
  ものは、読者が該当の発表にたどり着けないので、permalink が特定できるまで保留にします。

### 保留中の候補

掲載基準に届いていないもの。確認が取れ次第いれます。

| 事例 | 足りないもの |
|---|---|
| 日本漢字能力検定協会（2026-10-20、AI生成画像の誤字を公式Xで認めた） | 投稿の permalink |
| 味の素（2026-08-16、AI加工したレシピ画像の崩れを公式Xで謝罪） | 投稿の permalink |
| 集英社（掲載済み） | アカウントURLで掲載中。投稿単体の permalink に差し替えたい |

## 1件追加する手順

1. 一次情報のURLを確定する。発表元が当該組織であること、日付が明記されていることを確認する。
2. `AI_INCIDENTS` に1件追加する（既存のエントリーが書き方の見本です）。`id` は
   `YYYY-MM-組織-短いキーワード` 形式で、一度決めたら変えない。
3. `summary` は一次情報に書かれている事実だけを2〜3文で書く。原因の推測は書かない。
4. `impact` は公表されている数字のみ。公表されていなければ省略する（「不明」とは書かない）。
5. `sources` に `retrievedOn`（URLを確認した日）を入れる。1件以上必須。
6. このサイトに関連記事があれば `relatedArticles` にスラッグを入れる。
7. `npx astro check` が0エラーであることを確認してコミットする。

## 更新

- 当該組織が続報を出したら `summary` / `impact` / `response` / `status` を更新し、`sources` に続報を追加する。
- `status` は `investigating`（調査中）→ `responding`（対応中）→ `resolved`（収束）。
  組織側が収束を公表していない場合は `resolved` にしない。

## 訂正

- 誤りが判明した場合は、該当項目を直したうえで `summary` の末尾に訂正の事実と日付を1文で残す。
- 削除は、掲載基準を満たさないと判明した場合に限る。その場合もコミットメッセージに理由を残す。

## 公開の扱い

2026-11-03 に初版7件を掲載し、ページは公開状態になりました。

`AI_INCIDENTS` が空のあいだ、ページは「準備中」の表示になり、`noindex` が入り、
sitemap にも載りません（`isIncidentListPublished()` で切り替わります）。
1件でも追加すればインデックス対象になります。
