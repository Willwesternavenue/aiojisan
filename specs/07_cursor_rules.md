# Cursor Maintenance / Iteration Rules

## Role
Cursor is used after the initial scaffold is generated.

Use Cursor for:
- refactoring
- debugging
- UI polishing
- incremental feature additions
- query optimization
- styling adjustments
- integration fixes
- component cleanup

Do not use Cursor to reinvent the architecture unless necessary.

## Priorities
1. preserve clean structure
2. avoid duplicated service logic
3. keep server/client boundaries clear
4. improve usability without bloating the system
5. keep design restrained and consistent

## Coding Preferences
- TypeScript-first
- small reusable components
- descriptive naming
- no unnecessary abstraction
- clear comments only when helpful
- prefer explicitness over cleverness

## UI Preferences
- calm editorial workspace feeling
- not over-animated
- not flashy
- practical admin UX
- clean readable public pages
